# Требования к внешней интеграции с платформой "Умный дом"

## 1. Требования к безопасности

1. **Минимизация передаваемых данных (Data Minimization):** 
   - В партнёрскую систему передаётся только уникальный внутренний идентификатор собственника (UUID) и идентификатор объекта доступа (конкретная дверь/шлагбаум). Передача ФИО, телефона или других ПДн партнёру запрещена.
2. **Обработка биометрических данных:** 
   - В соответствии с 152-ФЗ, биометрические данные (снимки лица) относятся к специальной категории ПДн. PropDevelopment **не должна** хранить или передавать сырые биометрические шаблоны. Партнёр обязан проводить сверку биометрии на своей стороне или на защищённом edge-устройстве (домофоне), возвращая в PropDevelopment только результат события: `access_granted` или `access_denied` с привязкой к UUID.
3. **Шифрование данных:** 
   - Весь трафик между системами PropDevelopment и партнёром должен быть зашифрован с использованием TLS 1.2 или выше.
4. **Журналирование и аудит (Audit Logging):** 
   - Сервис `smart-home-integration-app` обязан логировать все команды на открытие и все полученные события от партнёра (время, UUID собственника, ID устройства, результат). Логи должны быть защищены от модификации.
5. **Защита от атак:** 
   - Реализовать Rate Limiting на стороне `smart-home-integration-app` для предотвращения brute-force атак или DDoS через API партнёра.

## 2. Протоколы аутентификации и авторизации

1. **Аутентификация "Сервис-Сервис" (mTLS):** 
   - Для взаимной аутентификации серверов PropDevelopment и партнёрской платформы использовать Mutual TLS (mTLS). Это гарантирует, что запросы приходят только от доверенных узлов.
2. **Авторизация API (OAuth 2.0 / JWT):** 
   - Использование короткоживущих JWT-токенов (access token) с ограниченной областью действия (scope), например, `smart_home:access:write`. Токены должны обновляться через refresh token или перевыпускаться по mTLS.
3. **Авторизация на уровне бизнеса (RBAC/ABAC):** 
   - Перед отправкой команды партнёру, `smart-home-integration-app` обязан сделать синхронный запрос к `tenant-core-app` для проверки актуальных прав доступа собственника (ABAC: имеет ли право этот собственник открывать эту конкретную дверь в данное время суток).

## 3. Организация взаимодействия между системами

1. **Синхронное взаимодействие для команд управления:** 
   - Использование REST API (HTTPS) для прямых команд из мобильного приложения (например, кнопка "Открыть дверь"). Ожидание подтверждения от партнёра с таймаутом не более 3 секунд.
2. **Асинхронное взаимодействие для событий (Event-Driven):** 
   - Использование Webhooks или Message Queue (например, Kafka/RabbitMQ, если партнёр поддерживает) для получения событий от партнёра (например, "Дверь открыта по распознаванию лица" или "Шлагбаум открыт по номеру автомобиля"). Это позволит мобильному приложению получать Push-уведомления в реальном времени без постоянного опроса (polling).
3. **Паттерн Circuit Breaker (Автоматический выключатель):** 
   - В `smart-home-integration-app` должен быть реализован Circuit Breaker. Если партнёрская система недоступна или отвечает ошибками, система должна быстро возвращать мобильному приложению понятное сообщение о временной недоступности сервиса, не блокируя потоки исполнения и не перегружая партнёра повторными запросами.
4. **Идемпотентность операций:** 
   - Команды на открытие должны быть идемпотентными (повторная отправка одного и того же запроса с тем же ID не должна приводить к непредсказуемым последствиям или множественным открытиям).
